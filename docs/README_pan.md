# pan.py — A股盘前 / 盘中 / 盘后全流程数据抓取

> 单文件 CLI。沿用 `stock3d.py` 的分段架构与铁律，但**完全独立**，不 import 也不依赖它运行。
> 全部输出为**中性事实与数值**，不含买卖建议、不做综合评分、不构成投资建议。
> **纯标准库**（`urllib` + `subprocess` 调 node），不需要 `requests` / `pandas`。

```
python pan.py prep                     # 盘前（外围/汇率利率/大宗/宏观/供给/消息/竞价）
python pan.py live                     # 盘中单次快照（指数量能/情绪/资金/板块轮动）
python pan.py post                     # 盘后复盘 + 次日前瞻
python pan.py all                      # 三段合并写一个 JSON
python pan.py post --pool data\user\持仓数据.md   # 附加个股复盘
python pan.py prep --date 2026-09-14   # 指定交易日
```

**交付物只有 JSON**：`data/pan/<YYYYMMDD>/<HHMMSS>_<phase>.json`，另在同目录覆盖一份
`latest_<phase>.json` 指针，便于取当日最后一次结果。不产出 md / HTML。

**跨日状态**：`post` 会把当日 today-only 的特色数据落到 `data/pan/state/<YYYYMMDD>/state.json`，
供次日 `prep` 引用「前一交易日连板股 / 炸板股的竞价表现」——这是必需的，因为同花顺的
涨停池 / 炸板池是 **today-only、无法补历史**。

## 一、参数

| 参数 | 适用 | 说明 |
|---|---|---|
| `prep` / `live` / `post` / `all` | — | 四个子命令，必选其一 |
| `--date YYYY-MM-DD` | 全部 | 目标交易日。默认今天；非交易日**回退最近交易日**并写 `note`；**未来日期不回退**（见铁律 5） |
| `--out DIR` | 全部 | 落盘基目录（默认 `<脚本目录>\data\pan`） |
| `--pool FILE` | `post` / `all` | 持仓/自选文件。自动识别「证券代码」列，兼容多列 / 表格 / 纯代码混排。不传则个股复盘子块标 `NA` |
| `--top N` | 全部 | 各榜单/名单保留条数（默认 20） |
| `--em-host URL` | 全部 | 覆盖东财 host（可重复）。**降级演练用**：`--em-host https://127.0.0.1:1` |
| `--no-cache` | 全部 | 忽略本地缓存（交易日历） |
| `--debug` | 全部 | 打印调试信息 |

## 二、三段各取什么

**分工原则（勿混）**
- **盘前 = 基准与风险点**：隔夜外围、汇率利率、资金面、当日供给、消息分层、集合竞价。
- **盘中 = 当下事实**：指数量能、情绪广度、资金流向、板块轮动、关键时点窗口。
- **盘后 = 定格复盘 + 次日前瞻**：收盘口径复核、龙虎榜、个股复盘、次日新股/解禁/公告。
- 实时类字段统一取「运行时刻的现值」：在 9:15–9:25 跑就是竞价数据，在盘后跑就等于收盘快照，
  `auction.口径说明` 会写明本次运行落在哪个 session。

### 盘前 `prep`

| JSON 块 | 内容 |
|---|---|
| `overseas` | `权益_隔夜`（道指/纳指/标普500/纳指100/A50期货/恒指期货）、`汇率`（CNH、美元指数）、`大宗商品`（WTI/布伦特/COMEX金/银/LME铜铝锌/CBOT大豆玉米）、`东财国际指数`（富时100/DAX/CAC40 及交叉源）、`债券收益率`（美债10Y=`171.US10Y`、中债10Y=`171.CN10Y`） |
| `shibor` | 中国货币网 Shibor：`隔夜_ON`、`7天_1W`、`各期限`（ON/1W/2W/1M/3M/6M/9M/1Y）、`前一日`、隔夜与 7 天的 `变动_bp` |
| `dr007` | 中国货币网 FRR 定盘利率：`FDR007`（即 DR007）、`FR007`、`FDR001`、`FR001`、`FDR014`、`FDR007_变动_bp` |
| `policy_calendar` | 央行 OMO / LPR / 宏观日历的**快讯关键词派生**口径：`顶层政策`、`行业政策`、`宏观日历_数据发布`、`当日快讯条数`。**标 DEGRADE**（非官方日历接口） |
| `supply` | `新股`（当日申购/当日上市/后续待申购，含发行价、发行万股、网上发行万股、募资亿）、`限售解禁`（当日解禁总市值亿、个股数、大额名单、类型、占总股本%）、`可转债`（口径说明） |
| `news_layers` | 消息分层：`顶层政策` / `行业政策` / `宏观数据`（快讯关键词过滤）、`个股公告`（巨潮，前一交易日）、`前一日龙虎榜`（同花顺席位榜）、`快讯源条数` |
| `auction` | `指数竞价`、`两市竞价成交额_亿`、`竞价涨跌家数`、`竞价涨停家数`、`竞价板块强弱`（概念板块前5）、`同花顺竞价快照` / `同花顺竞价基准`（官方端点）、`前一日连板股竞价表现`、`前一日炸板股竞价表现`（读本地 state）、`口径说明` |

### 盘中 `live`

| JSON 块 | 内容 |
|---|---|
| `indices_volume` | `指数_同花顺`（四大核心 + 上证50/沪深300/中证500/中证1000，含涨跌幅/振幅/成交额）、`指数_东财`（交叉源）、`两市成交额`（沪/深/北交所/合计，亿元）、`分时均价线`（上证指数、创业板指：现价、分时均价 VWAP、现价相对均价%、分钟数） |
| `sentiment` | `广度`（涨跌家数、上涨占比、涨跌幅超5%家数、涨跌停家数×阈值口径、一字/T字涨停、ST 拆分、平均/中位数涨幅、无行情家数）、`双源交叉`（东财阈值口径 vs 同花顺涨跌停池并列）、`涨停池`/`跌停池`/`炸板池`（同花顺，含封单额、连板数、涨停原因）、`连板梯队`（各梯队数量、最高连板、名单）、`个股人气榜`（成交额/换手/振幅/主力净流入/净流出 TOP） |
| `funds` | `北向资金`（保留字段 + 停披露说明）、`南向资金`（合计/沪市港股通/深市港股通净买入_亿，含原始值）、`沪深港通额度`（口径说明：是额度余额不是净流入）、`主力资金_两市净流入_亿`、`行业主力资金`（净流入/净流出 TOP10）、`两融`（融资余额/融资买入/融券余额/融券余量） |
| `sectors` | `行业板块`/`概念板块`（领涨/领跌，含板块内涨跌家数、领涨股、主力净流入）、`板块内部结构`（领涨前5板块的成分统计：板块内涨停数、涨幅超5%数、龙头）、`板块轮动速度`（与前一交易日领涨板块的重合度）、`口径说明` |
| `关键时点` | 当前时刻落在哪个观察窗（开盘定调 9:30–10:00 / 趋势验证 10:00–11:30 / 午后验证 13:00–14:30 / 尾盘定调 14:30–15:00） |

### 盘后 `post`

包含上面 `indices_volume` / `sentiment` / `funds` / `sectors`（收盘口径复核），另加：

| JSON 块 | 内容 |
|---|---|
| `dragon_tiger` | 同花顺龙虎榜：当日 / 前一日的 `榜单`、`机构席位`、`游资席位`（净买额、买入额、卖出额、涨跌幅、净占比、热度排名、游资净额） |
| `dragon_tiger_em` | 东财龙虎榜交叉源（含**上榜原因**与净买额，按净买额降序） |
| `stock_review` | 个股复盘：`--pool` 标的的涨跌幅/最新价/量比/换手/振幅/成交额/主力净流入/净占比 + 全市场 TOP 榜。**不传 `--pool` 标 `NA`** |
| `next_day` | 次日前瞻：`次日`（交易日历推算，无未来日期时按跳周末估算并标注）、`新股_申购`/`新股_上市`、`限售解禁`（总市值+名单）、`次日事件`、`晚间公告`（巨潮当日公告按时间倒序） |
| `overseas_evening` | 外围晚间走势（结构与 `overseas` 一致，收盘后再取一次） |
| `state_saved` | 本次落盘的跨日 state 路径 |

## 三、交付格式与落盘

```
data/pan/
  <YYYYMMDD>/
    <HHMMSS>_prep.json      按次快照，随时可跑多次留痕
    <HHMMSS>_live.json
    <HHMMSS>_post.json
    <HHMMSS>_all.json
    latest_prep.json        覆盖式指针，取当日最后一次
    latest_live.json
    latest_post.json
    latest_all.json
  state/
    calendar.json           同花顺交易日历缓存（当日有效）
    <YYYYMMDD>/state.json   跨日状态：连板天梯、涨停/跌停/炸板池、领涨板块与概念、广度
```

单次快照结构：

```jsonc
{
  "schema_version": "1",
  "phase": "prep|live|post|all",
  "generated_at": "2026-09-11T23:46:53+08:00",
  "trade_date": "2026-09-11",
  "is_trading_day": true,
  "trading_day_verified": true,     // 未来日期为 false（日历窗口不含未来，仅按周一至周五粗判）
  "trading_day_note": null,
  "session": "盘后",
  "sources": { "<块名>": { "status": "OK|DEGRADE|FAIL|NA", "detail": null } },
  "data":    { "<块名>": { } },
  "degrade": ["policy_calendar: ..."],
  "notes":   ["...数据口径与边界说明..."],
  "meta": { "node_calls": 24, "http_calls": 249,
            "pool_sizes": {"财联社电报": 100, "...": 0},
            "pool_fails": {} }
}
```

- `sources` 逐块记录状态与失败原因，与 `data` 一一对应；`FAIL` 块的 `data` 为 `null`，**绝不用近似值/示例值/0 顶替**。
- 跑 `all` 时三段的块合并进同一份 JSON（实测 16 块），`关键时点` 与 `state_saved` 是 `data` 下无 `sources` 条目的附加块。

## 四、铁律与已知边界

**数据源确实拿不到的项（已显式标注，不静默缺失）**

| 环节 | 拿不到的项 | 处理 |
|---|---|---|
| 盘前 | 央行公开市场操作（逆回购/MLF/SLF 投放量、中标利率、到期量）、LPR 报价、宏观日历官方值 | 无稳定公开接口（东财 datacenter 报表名全部实测 404、财联社财历 errno=50101）→ 降级为**快讯关键词派生**，标 `DEGRADE` |
| 盘前 | 可转债申购/上市日历 | 东财无可稳定报表口径 → 快讯口径，字段内注明 |
| 盘前/盘中 | 北向资金实时与日度净流入 | 交易所自 2024-08 起停止披露 → 保留字段、值 `null`，以**南向 + 主力资金 + 龙虎榜席位**替代观察 |
| 盘中/盘后 | 严格申万一级/二级行业口径 | 两个数据源都没有 → 用东财行业板块 + 同花顺行业指数，`口径说明` 注明 |
| 盘后 | 龙虎榜个股的「涨停原因分类」 | 同花顺返回的是热度排名与净额，不含原因文本；原因文本在 `dragon_tiger_em`（东财 EXPLANATION） |
| 全流程 | 个人持仓的成本/盈亏 | 属账户数据，`--pool` 只读代码清单，不猜测成本 |

**铁律**
1. **stdout 只输出 ASCII**：PowerShell 管道会把 UTF-8 中文按 GBK 解码成乱码，状态行一律剥离非 ASCII 字符，中文内容只进文件。
2. **失败绝不伪装**：任何源失败都落显式 `[FAIL]`/`DEGRADE` 与原因；缺失一律 `null`，**严禁置 0 冒充数据**。
3. **名称⇔代码双向一致**：中文名必须精确匹配同名 thscode，否则报错不取数。同一 6 位代码同时命中「场外基金(.OF)」与「A股/ETF」时，优先交易所上市品种（a-share / fund-etf / fund-lof / fund-reits），仍并列才报错。
4. **不适用 ≠ 失败**：非交易日、today-only 跨日无本地 state、未传 `--pool` 等场景标 `NA`，不计入降级统计。
5. **过期日历不许反推**：同花顺交易日历窗口实测只覆盖到**今日**。因此（a）未来日期不做「非交易日回退」，否则 9/14 会被误判并悄悄回退到 9/11；（b）次日交易日无未来日期时按「跳过周末的下一自然日」估算，并置 `次日是否来自交易日历=false` + 说明不排除法定节假日。
6. **双源只并列不裁决**：广度/情绪/龙虎榜同时给东财与同花顺两套数，冲突只在 `双源冲突提示` 里点名，不自动择一。

**已知边界与实测口径（勿随意改参数）**
- **东财 `clist` 的 `pz` 上限是 100**（传 200/500/1000 都只回 100 行），全市场需分页 ~60 次。
- **按涨跌幅排序分页会漏数据**：`fid=f3&po=1` 时实测只拿到 5553 只（并列值导致跨页错位），改用 **`fid=f12&po=0` 按代码稳定分页**才拿满 5913 只。
- **`push2` 主域名时段性拒连**，`push2delay.eastmoney.com` 实测可用 → 作为首选 host，并做 host 轮换 + 指数退避，可用 `--em-host` 演练降级。
- **南向资金原始单位是百万元**（亿元 = 原值 / 100）：由 `006 = 002 + 004`（南向合计 = 沪市港股通 + 深市港股通）、`005 = 001 + 003`（北向合计）两个恒等式，加 2023 年北向真实量级校准得出。原始值一并保留在 `原始值_百万元`。
- **`kamt` 接口返回的是额度余额，不是净流入**：实测 `dayNetAmtIn` 恒等于日额度（4200000 万元 = 420 亿），北向 `hk2sh/hk2sz` 自 2024-08 起为 0 且 `status=3` 表示关闭 → 只作额度展示，**不当作资金流**。
- **DR007 在 `FrrHis` 的 `frValueMap` 里**：响应顶层是 `records[]`，每条的利率值在 `frValueMap`（`date`/`FDR007`/`FR007`/`FDR001`/`FR001`/`FDR014`），直接读 `record["FDR007"]` 会全为 `null`。`data` 节点只有 `baseCurveCfgList` 配置，没有值。
- **Shibor 必须带 `pageNum`/`pageSize`** 才会返回 `records`（否则只回配置）。
- **同花顺龙虎榜字段名**：`net_value` / `buy_value` / `sell_value` / `change`（**小数**，需 ×100 得涨跌幅%）/ `net_rate`（小数）/ `hot_rank` / `hot_money_net_value`。按 `net_buy_amount` 之类取名会全 `null`。
- **腾讯分时的 4 列是「时间 价格 累计量 累计额」**，不是均价；且响应里 `data.<sym>.data.data` 直接是**字符串数组**（不是 `;` 拼接的长串）。分时均价用分钟增量自算 VWAP。
- **东财新股 `ISSUE_NUM` 单位是万股，`ONLINE_ISSUE_NUM` 单位是股**（募资 = 发行价 × ISSUE_NUM ÷ 1e4）。
- **东财解禁 `LIFT_MARKET_CAP` 单位是万元、`CURRENT_FREE_SHARES` 单位是万股、`TOTAL_RATIO` 是小数**（×100 得%）。按元/股直接除会整体差 1e4。
- **`market.auction-snapshot` 与涨停/跌停/炸板池都是 today-only**；涨停池/跌停池/炸板池支持 `--date-ms`，但**没有当日的本地 state 就无法还原「前一交易日的连板/炸板名单」**，此时子块标 `null` + `state_note`。
- **涨跌停是「阈值口径」**：按板块与 ST 规则（10%/20%/30%/5%）对全市场涨跌幅做阈值判定，与同花顺官方涨跌停池口径会有差异（实测同一天 东财阈值 49 vs 同花顺 40），两者并列、不裁决。
- **两市成交额按代码前缀粗分**：6=沪、0/3=深、43/83/87/88/92=北交所，与交易所口径可能有极小差异。
- **东财快讯 `req_trace` 必填**，漏掉返回「code=0 + 空数组」的静默失败；行键在 `list` / `fastNewsList` 之间变动，两个都收。
- **财联社 `rn` 上限 50**，超过会「errno=0 但数组为空」地静默失败；签名 `md5(sha1(sorted query))` 必须对实际发出的参数串计算。
- **新浪 `hq.sinajs.cn` 必须带 `Referer: finance.sina.com.cn` 且按 GBK 解码**；`gb_*`（美股指数）、`hf_*`（期货/大宗）、`fx_*`（汇率）、`DINIW`（美元指数）字段位不同，代码内分别解析。
- **巨潮公告不带 `stock` 参数即为市场级查询**（`seDate` 单日），实测可用；`post` 的晚间公告是**按时间倒序前 N 条，非全量**。

## 五、维护须知

- 单文件，按 `# ===== [SEC-nn] 标题 =====` 分段；`Select-String -Path pan.py -Pattern '^# ====='` 可列出骨架。
- 改完必须跑：
  ```powershell
  python -c "import ast,io; ast.parse(io.open('pan.py',encoding='utf-8').read())"
  python pan.py --help
  python pan.py live --top 3 --out $env:TEMP\pan_smoke        # 冒烟
  python pan.py live --top 3 --em-host https://127.0.0.1:1    # 东财降级演练（应显式 FAIL 且退出码 0）
  ```
- **保留循环**：取一次快照的函数（`fetch_indices_volume` / `fetch_sentiment` / `fetch_funds` /
  `fetch_sectors`）都是无副作用纯函数，`run_live` 只调用一次。后续要加常驻盯盘，在 `run_live`
  外层套循环即可，本期**刻意不暴露 `--watch`**，避免误用。
- 刻意保留的分离：`num()`（缺失→`None`，数据口径）与 `_f()`（缺失→`0.0`，仅用于求和的内部累加）
  以及 `scale()`（可空换算，缺失保持 `None`）——勿统一。
- 新增数据块时：先在最外层 try 内取数，用 `put(ctx, rep, "块名", 值, 状态, 说明)` 落库，
  让 `sources` 自动带上状态；`FAIL` 块的值必须传 `None`。
