# webui — aiplan 的浏览器控制台

> 把 `aiplan.py` 的 CLI 能力搬到网页：运行研判、看报告、查历史、改配置、看大盘快照、按模块荐股。
> **零第三方依赖**（只用 Python 标准库），**不修改** `aiplan.py` / `pan.py` / `stock3d.py`。
> 报告仍由大模型生成，**不构成投资建议**。

## 一、启动

```powershell
python main.py                         # 推荐：统一入口，默认 http://127.0.0.1:8765，自动开浏览器
python main.py webui --port 9000       # 换端口
python main.py webui --no-browser      # 不自动开浏览器
python main.py webui --host 0.0.0.0    # 局域网监听（口令见下节，源码内无默认值）
cd src; python -m webui --port 9000    # 等价写法：直接跑包
```

也可以直接双击根目录的 **`启动WebUI.cmd`**（脚本内含 Python 缺失提示与端口占用提示），
或执行 `scripts\serve.cmd 9000` 指定端口。
需要让手机或其它局域网设备访问时，直接双击 **`启动WebUI局域网.cmd`**；首次运行会请求一次管理员权限，
添加仅允许本地子网访问 TCP 8765 的防火墙规则。启动窗口会打印桌面与手机版局域网地址：手机直接打开 `/m`，
其它设备也可打开根地址；登录页输入启动窗口打印的访问口令，从 `/m` 发起的登录完成后会回到手机版。

> 目录位置：控制台代码在 `src/webui/` 包内（路由 `webserver.py`、路径真源 `paths.py`、
> 荐股 `pick.py` / `pick_run.py` …，模块地图见 [ARCHITECTURE.md](ARCHITECTURE.md)），
> 前端是 `static/js/{core,ui,views}` 的原生 ES 模块，**无构建步骤**，改完刷新页面即生效。
> 模块化之后入口从 `/app.js` 换成 `/js/main.js`，旧页面缓存会 404，请按 Ctrl+F5 强刷一次。

默认只监听 `127.0.0.1`；非回环地址会强制密码登录，口令按 **`--password` → 环境变量 `AIPLAN_WEBUI_PASSWORD` → 本地 `config/webui配置.json` 的 `密码` 字段 → 随机生成** 的顺序解析，成功后通过 Cookie 保持 7 天。默认口令不写进源码，避免公开仓库等于公开口令；想固定手机登录口令，就在 `config/webui配置.json` 写 `{"密码": "你的口令"}`，该文件已在 `.gitignore` 内。局域网入口仍只应在可信网络临时使用，**不要**暴露到公网。

## 二、九个页面

桌面根地址和手机专用入口 `/m` 都默认进入**总控台**。手机版复用同一套九页数据与操作，隐藏桌面侧栏，
底部常驻「总控台 / 研判 / 报告 / 持仓 / 更多」，“更多”内含自选、荐股、模型配置和大盘快照。

### 交易流：一笔资金 + 多只标的，从建仓盯到清仓（人工体检 + 盘后重算）

- **一条流 = 一笔流资金 + 若干只标的**：`data/ai/flows/F-<YYYYMMDD>-<NN>.json` 里存流参数（流资金 / 目标收益率 / 最大亏损 / 备注）、标的清单（每只带 代码 / 名称 / 打法 / 分配资金 / 期初 / 成交 / 持仓 / 盈亏 / 计划 / 体检 / 事件 / 提醒状态）与流级事件；全局设置（接近带 / 轮询档位 / 盘后重算时间 / 打开页面自动补跑）在 `data/ai/flows/settings.json`。**老结构 `<代码>-<起始日>.json` 读入时自动升级成 v2**（折成一只标的），不用手工迁移。
- **资金是「流」的属性**：开流只填流资金 / 目标收益率 / 最大亏损，标的在流里随时加。`目标盈利_元 = 流资金 × 目标收益率`、`最大亏损_元 = 流资金 × 最大亏损`；每只标的按自己的**分配资金**分摊这两个金额，页面同时显示「按流资金」和「按投入成本」的收益率。**流内所有标的的分配资金之和不得超过流资金**（加标的、改标的、改流资金三处都拦；加标的不填分配资金就取剩余）。**一只标的只属于一条流**：同一标的在别的流里还没结束时不允许再加 / 再开。
- **打法决定计划的时间尺度**：每只标的选一种——**超短线**（1-3 个交易日，止损收紧 1%-3%，到小目标就落袋）/ **短线**（1-5 个交易日，3-5 日节奏）/ **波段**（2-6 周，容忍更宽波动、分批加减仓）。打法会写进事实包与提示词，模型据此出买点、止损与止盈；后续想换打法在卡片上点「改打法」。
- **口径写死**：盈亏用平均成本法（买入把手续费摊进成本、卖出按平均成本结转已实现），手续费复用 `aiplan.trade_cost`（A 股卖出含印花税、双边过户费，ETF 免）；`合计 = 已实现 + 浮动`，浮动按现价（取不到用最近成交价并标来源）。
- **达标与止损只提示**：`合计 ≥ 目标盈利` → 黄条「达标，建议清仓」；`合计 ≤ -最大亏损` → 红条「触及最大亏损，建议止损」；状态切换（达标 / 止损 / 结束）由你确认；某只标的持仓归零后自动结算为 已达标 / 未达标清仓 / 已止损，**流里所有标的都结束后整条流自动结束**。
- **成交来自两处**：同花顺「同步持仓」写进 `data/user/交易台账.md` 的当日成交（按委托序号去重）会自动并入，也可以手工补录 / 纠错；只并入**该标的且不早于它加入这条流那天**的成交，更早的会在页面注明「未并入 N 笔」。补录或删除成交只重算持仓与盈亏，**不改计划**。
- **计划与体检都是「你点才跑」**：`POST /api/jobs {kind:"flow_plan"|"flow_check", 流编号, 代码:[…]}`。计划可以一次只跑一只，也可以「全部重算」（按流内标的顺序各调 1 次研判档，可选复核档）；体检必须指明是一只标的（只有一只时自动带上）。计划产物与标的跟踪共用一套：落 `data/ai/track/<数据交易日>/<HHMMSS>_<代码>_track.json|.md`，字段与 aiplan 报告一致，所以**报告页的 K 线 / 关键价位 / 实盘复核卡可以直接打开**；证据链里最前面永远是「交易流状态（成交与盈亏，权威口径）」，里面带流参数、这只标的的打法与分配资金、同流其他标的的摘要。
- **复核档是可选的**（批注 1）：「计划与体检」卡新增 **「含复核档（多一次模型调用）」** 勾选框——只有勾上才会跑复核档，报告页才会出现「复核档质询」卡；没勾时报告头写「复核 已跳过 ⓘ」，鼠标停上去（以及「复核档质询」卡）会写清原因；profile 里没有复核档时写的是另一句原因。
- **计算计划 = 机械打分定约束 + 模型出价位**（批注 1）：点「计算」时先对**这一只**标的跑全量 6 模块机械打分（`mechstock.score_one`：1 次东财 ulist 取行 + 复用 `mechdata` 的日K / 财报 / 宏观 / 行业 / ETF / 北向 / 质押 / 公告 / 股东 / 龙虎榜取数，与荐股同一套阈值与原始值纯函数），据此写死**硬约束**（`flowplan`）：档位 **≥70 可满配 ｜ 55-70 ≤2/3 ｜ 40-55 ≤1/3 且只减不加 ｜ <40 或一票否决只减不加（持仓按文件口径一次性清仓）**；**亏损预算 = 该标的分配资金 × 流最大亏损%**（股数上限 = 预算 ÷（买入价 − 止损价），100 股整数倍）；**打法止损幅度上限**（超短线 3% / 短线 5% / 波段 8%）。事实包里新增两章（**机械打分（100分制）** 与 **硬约束（不可越界）**，永不裁剪），模型在框子里给买点 / 减仓 / 止损 / 止盈价位；**越界由程序自动校正并逐条标注**（`约束校正`：股数下调、止损收窄、买入区间上移、条目作废 + 原因），校正记录写进产物、详情卡与页面上的计划表（作废条目整行划掉 + 「已作废」徽章）。止盈不做硬改：若按最近止盈点达不到本标的目标盈利，页面标注「完成 X%」；持仓按止损算的敞口超过亏损预算时也提示。
- **盘后重算**：过了设定时间（默认 15:10、仅交易日）且今天还没重算 → 页面黄条按「流 + 标的」列出待重算项 + 一键重算；**没有常驻进程，所以不会无人值守自动跑**；想省事可以打开「打开页面自动补跑」（默认关）。
- **删除与移除**：「移除标的」把它从流里拿掉（成交、体检、计划引用一起删，分配资金退回这条流，`data/ai/track` 里的计划文件仍在）；「删除流」把整条 JSON 移入 `data/ai/.trash/`（超过 7 天真删）；跟踪清单里的计划产物另有「删除」入口，口径相同。

### 荐股：全大盘扫描 + 模型为主 + 严格机械打分

### 报告页的四条口径（批注 1-4）

- **复核为什么是「已跳过」**：计划任务只有在你勾了复核档时才会跑复核。交易流页「计划与体检」卡新增 **「含复核档（多一次模型调用）」** 勾选框；没勾时报告头显示「复核 已跳过 ⓘ」，鼠标停上去能看到原因（「本次没有勾选复核档…」），「复核档质询」卡也会把原因与复核档是什么写清楚。profile 里没有复核档时写的是另一句原因。
- **数据日期标签**：报告头新增 **数据日期** 标签（鼠标停上去看全：实时报价时点 / 日K 最新交易日 / 机械打分取数时间 / pan 快照交易日 / stock3d 快照日期 / 计划适用交易日），同一份清单也逐行进「运行元信息」表。只有写了 `数据.事实包日期` 的产物（交易流与标的跟踪的计划）才有这个标签，旧产物不显示、不拿交易日冒充。
- **K 线图例**：支撑 / 压力 改成 **买点 / 卖点**，目标改成 **止盈点**（与交易计划的操作口径统一）。
- **作废的条目不上桌**：被硬约束作废的计划条目**不进「交易计划」主表、也不画到 K 线上**（同价的买点/卖点/止盈点线一起隐藏，K 线右上角标「已隐藏 N 条作废价位的线」），它们收在下方一张**默认收起**的「已作废的条目」表里，逐条写作废理由（股数划掉）。

- **候选池**：东财全 A（约 5900 只）按成交额降序 → 排除规则（ST / 次新 / 低价 / 低成交默认开，科创板北交所默认关）→ 候选池 400 只；`data/cache/mech/pool_<日期>.json` 当天缓存。
- **机械打分**：严格照根目录 `机器打分逻辑.txt` 的 100 分制（模块1 宏观 15 ｜ 模块2 行业景气 20 ｜ 模块3 基本面 25 ｜ 模块4 技术面 25 ｜ 模块5 资金筹码 10 ｜ 模块6 风险合规 5）+ 一票否决（ST 退市 / 一字跌停停牌 / 流通市值 < 20 亿 / 连续两年亏损且营收 < 1 亿对全池；立案谴责 / 质押 ≥ 85% / 近 30 日减持 ≥ 2% 只对送模型的前 150 只）。**阈值逐条照抄文件**，不做主观修正；口径文件有 sha256 基线（`scripts/spec_baseline.json`），改口径必须显式 `python scripts/check.py --update-baseline`。
- **缺失口径**：拿不到数据源的项（沪深300 PE 近10年分位 4 分、近20日北向净流入 3 分、行业 PE 近10年分位 4 分；审计意见否决项）**只从分母里去掉**，不记 0、不摊权，机械分 = 实得 ÷ 可得 × 100，页面与产物逐条列出缺失原因。当前可得满分通常 76-89 分（取决于当天成交额 / ETF / 商誉等小项能否取到）。
- **两次打分**：全池 400 只用批量可得的字段先打一遍（只作初筛），取前 150 只补上公告 / 股东户数 / 十大流通股东 / 10 日主力资金后**重算**，最终机械分这才进推荐榜的辅助列。
- **模型层**：前 150 只的**原始数据**（量价、财务、行业、板块热度前后 10、大盘）拼成事实包，**不含机械分**（避免锚定）；一次调用产出「市场风格 + 推荐榜 30 只（评分 / 理由 / 打法）」；模型失败时明确标注「本次没有模型评分」，榜单回退机械分排序。
- **耗时与限速**：全池逐股日K（东财优先，被限流时自动回退腾讯前复权日K并写降级）与逐股明细都是串行 + 间隔；一轮大约 5-10 分钟，**当天二次运行**复用 `data/cache/mech/` 里的日K / 财报 / 质押缓存，会快很多。写入白名单只有 `data/cache/mech/`（缓存）与 `data/ai/pick/`（产物）。

### 大盘评分：机械 7 : 模型 3（批注 1，旧「大盘走势预测」已下线）

- **机械分（权重 7）**：严格照根目录 `大盘评分逻辑.txt` 的 100 分制 6 模块 27 个分项（估值 25 ｜ 货币与宏观流动性 20 ｜ 场内资金 20 ｜ 技术趋势 15 ｜ 市场情绪 10 ｜ 外围传导 10），**阈值逐条照抄文件**，不做主观修正；口径文件与 `机器打分逻辑.txt` 一样有 sha256 基线，改口径必须显式 `python scripts/check.py --update-baseline`。
- **数据源**：中证指数官网（沪深300 / 中证500 的 PE 十年序列，按年分段抓、缓存 30 天 → 10 年分位）；东财（沪深300 日K 300 根与前复权月K、上证综指 + 深证综指日K、指数资金流历史、全市场 clist 汇总、M2 同比与 3 个月拆借利率报表、美元指数与标普500 日K）；pan 快照（中债 10Y、两融、广度 / 涨跌停 / 连板 / 主力净流入）；中国货币网 / 新浪（人民币兑美元）。「近5/10/20 日」类分项**能回抓就回抓**（指数资金流历史、指数成交额），抓不到的**逐日积累**在 `data/cache/mkt/hist/daily.json`（每次算分记一份，不足天数就标缺失）。
- **无数据源的 7 项（32 分）**：沪深300 PB-LF 十年分位、A 股 ERP 十年分位、DR007、社融存量同比、近 20 日北向净流入、股票型 ETF 累计净申购率、CRB 近 20 日 —— 如实标「无数据源」并**只从分母剔除**（不记 0、不摊权），机械分 = 实得 ÷ 可得 × 100。以后接上付费源（理杏仁 / Wind / iFinD / Tushare）只需在 `src/webui/mktdata.py` 补一个取数函数，阈值不动。
- **模型分（权重 3）**：点「生成解读」时 **1 次模型调用**，**盲评**——事实包里只有 pan 快照与原始数据（PE/分位、国债、M2、拆借、两融与流通市值、成交额、主力资金、涨停跌停与换手、宽度样本、美元指数 / 标普500 / 人民币），**不含机械分与任何阈值**；模型给一个 0-100 分 + 80 字理由 + 精简解读（一句话结论 / 风险与应对 / 操作建议 / 数据依赖）。产物落 `data/ai/market/read_<YYYYMMDD>/`（含 `latest_read.json` 与同名 `.md`），日报 token 与费用照常记录。
- **总分 = 机械分 × 0.7 + 模型分 × 0.3**（1 位小数）；当天还没生成模型分时，总分先按 100% 机械显示并在卡上写明「模型分未生成」，生成后自动变 7:3；两者相差 ≥ 15 分时卡上给一行「分歧较大」提示。**不做仓位映射、不做硬约束**，只展示 + 写进事实包。
- **计算时点**：不设 20:00 定时（没有常驻进程）。打开页面读当天缓存，没有就同步算「快速版」（跳过宽度样本与全市场汇总，这两项标未算），卡上「重新计算」跑**全量任务**（`POST /api/jobs {kind:"mkt_score", full:1}`，含宽度样本 400 只逐股日K与全市场汇总，可中断、零成本、当天缓存）；「生成解读」= `POST /api/jobs {kind:"mkt_read"}`（1 次模型调用，可中断；失败也照常落盘并如实写 error，不谎报分数）。
- **事实包联动**：交易流「计算计划 / 体检」与荐股的事实包新增 **「大盘评分（机械 7 : 模型 3）」** 章节（总分 / 机械分 / 模型分 / 6 模块小计 / 无数据源与缺失清单 / 模型一句话结论，≤400 字且永不裁剪）。

### 数据新鲜度：过期快照自动清理

- **事实包不许用过期数据**（用户硬要求）：aiplan / stock3d / pan 都是「扫目录取最新一份」，所以启动任何任务前会先把**早于最近一个交易日**的行情快照**直接删除** —— `data/pan/<日期>/`、`data/pan/state/<日期>/`、`data/s<日期>/`（stock3d 快照）都会删掉（**不进回收站**：过期行情没有保留价值）；`data/pan/state/calendar.json`（交易日历）与用户的报告/计划产物不动。
- 清理结果会随任务启动返回，页面弹一条提示（「已删除 N 份过期行情快照…」）；以前留在 `data/ai/.trash/stale/` 的条目也会一并清掉。
- 想恢复最新背景：`python main.py pan post`（大盘/量能）与 `python main.py stock3d pull <代码>`（个股消息面），或直接在「运行研判」里跑一次；没有新鲜数据时事实包会在降级清单里写「没有 pan 快照」，不会拿旧的冒充。
- 测试用 `AIPLAN_NO_PURGE=1` 关闭清理（测试不该动用户数据）；清理逻辑在 `src/webui/freshness.py`，同进程 60 秒最多扫一次。

## 三、数据与写回策略

- **只读复用**：后端 `import aiplan`，持仓解析、账户校验、报告读取都走 aiplan 自己的函数，口径与 CLI 完全一致。
- **自选股与持仓分开**：`自选股.md` 是纯关注清单，只用于挑标的与批量研判，不参与仓位与费用测算（那只看 `持仓数据.md` 与 `账户配置.json`）。
- **写回白名单**：只有这三个文件能通过网页保存——`持仓数据.md`、`账户配置.json`、`模型配置.json`。
- **荐股只读行情**：除「加入自选」外不写任何配置；产物单独落 `data/ai/pick/<YYYYMMDD>/`，当天的扫描 / 财报 / 日K 缓存落 `data/cache/mech/`，**不进** `plan_log`、不参与复盘；删除时移入回收站。报告产物按「每个标的只留最新一份」自动清理（移入回收站）。
- **交易流只读行情**：交易流页只写 `data/ai/flows/`（流状态 + 设置）与 `data/ai/track/`（计划产物）、`data/user/跟踪标的.md`（计划来源清单）；除「加入自选」外不写配置与持仓，产物**不进** `plan_log`、不参与 aiplan 的复盘链路；总控台 / 实盘复核读它是单向只读。
- **回收站 7 天过期**：`data/ai/.trash/` 下的条目（报告、计划历史快照、荐股结果）**超过 7 天自动真删**，服务启动时清理一次、打开报告页 / 回收站接口时惰性清理（同进程 30 分钟最多扫一次）。页面逐条显示「剩余天数」，≤2 天标黄。**真删不可恢复**，需要留档请先搬回原位。
- **内容无变化就不写**：提交内容与文件一致时跳过，不写盘也不产生备份。
- **真改动了才落盘**：先备份成同名 `.bak`，再按**原文件的换行风格**（LF / CRLF）、BOM、结尾换行写回，尽量不制造无意义的 diff。
- **先校验后写入**：JSON 必须合法；账户要求「总资金」> 0；模型配置要求 `providers` / `profiles` 非空。校验失败一律拒绝并且不碰原文件。
- **任务产物定位**：跑完按 `data/ai/<YYYYMMDD>/` 里 `HHMMSS_<phase>.json` 的 mtime 取本次最新；`--dry-run` 则定位 `.factpack.md`。失败（退出码 3）时报告照样落盘并在页面打开，标注 `[FAIL]`。
- **中断**：Windows 下用 `taskkill /F /T` 结束整棵进程树，不会留下 `pan.py` / `stock3d.py` 残留进程。
- **同花顺同步**：`holdings_sync` 任务只读取已登录客户端；成交口径是**近一周**（当日成交 + 历史成交页，近 7 个自然日，按委托序号自动去重后写台账）——只拉当日成交在凌晨/非交易日会拿到空数据，所以不再因为非交易日跳过成交。校验通过后更新持仓文件、账户总资金、`data/user/交易台账.md` 和 `data/holdings/ths/snapshots/`。预览、客户端未登录或校验失败时不写业务文件。若出现复制验证码，任务会暂停并在页面弹出图片，人工填写后继续；验证码不会写日志，也不做自动识别。

## 五、控制台为什么不再是乱码

`aiplan.py` 的既有铁律是「stdout 只出 ASCII，中文一律进文件」，直接看命令行会满屏 `?`。网页端跑的是 `src/webui/run_aiplan.py` 这个包装器：它在导入 aiplan 之后，只把 `aiplan._ascii()` 换成恒等函数、并把标准输出切到 UTF-8，**没有改动 `aiplan.py` 一个字**。所以网页控制台能看到完整中文（事实包章节名、dry-run 提示、失败原因等）；你直接 `python aiplan.py ...` 的行为保持原样（`python main.py aiplan ...` 会自动走这个包装器）。

## 六、已知边界

- **控制台里的中文会显示成 `?`**：这是 `aiplan.py` 的既有铁律（stdout 只出 ASCII，中文一律进文件）。网页如实转发、不做猜测还原，但会在下面补一段中文**诊断**说明失败原因与下一步（例如退出码 4 = 选中标的不在本地数据里）。**报告、配置、页面文字本身都是正常中文**。
- **退出码 4 最常见的两种情形**：① 开着「复用已有数据」但该标的还没抓过（缓存里没有）→ 警告会提前提示，关掉开关重跑即可；② 代码写错或该标的数据源拿不到 → 确认代码是 6 位（如 `002463`）或 `002463.SZ` 形式。
- **退出码原样透传**：`0` 正常 ｜ `2` 参数/配置错误 ｜ `3` 模型调用失败 ｜ `4` 数据缺失。页面按退出码显示「完成 / 失败」，不会把失败伪装成成功。
- **`check-model` 可能很慢**：如果 profile 的研判档是推理模型（如 `glm-5.3`），ping 会先花 reasoning token，可能耗时数分钟；换 `*-全闪` 档自检通常 1～2 秒。
- **一次只研判一只标的**：沿用 aiplan 的单标的约束，本页不做批量与定时。
- **大盘走势预测是模型产物**：点一次按钮 = 一次真实模型调用（产生 token 费用）。它复用所选 profile 的「研判档」，结果只落 `data/ai/market/`，**不写进 `plan_log`**，也不参与个股报告。
- **K 线按需自动拉取**（批注 3）：先读本地缓存 `data/history/<thscode>.json`，没有就自动取日K（东财 push2his 优先，被限流时回退腾讯前复权），当日缓存在 `data/cache/mech/kline_<日期>/`；两个源都取不到时页面才提示（可先 `python main.py stock3d pull <代码>` 落一份本地缓存）。
- **综合评价与精确价位是确定性渲染**：综合评价只是按情景概率机械汇总，不会再让模型二次判断；计划里的价位依据取自同一份报告的「关键价位」，按 2% 邻近匹配，匹配不到就只显示数值。
- **任务记录在内存**：重启服务后，运行页的历史输出清空（落盘的报告与 plan_log 不受影响）。
- **荐股固定花一次模型调用**：跑之前先抓板块与成分股（不花钱），最后把机械榜交给所选 profile 的**研判档点评一次**（不调复核档）。模型失败时**机械榜仍然落盘**，页面会明确标注「本次没有模型点评」，不会掩饰。
- **荐股机械分不是收益预测**：板块分 = 动量 35 + 资金 30 + 广度 20 + 量能 15；个股分按模块换权重（短线偏动量+资金，中线偏估值+流动性，长线偏估值+市值+长期趋势），所有「分位」都在**本次候选池内**计算。缺少的字段不计分（按可用权重归一），不会拿 0 顶替。
- **荐股只依赖东财（纯 HTTP，不调 node）**：板块行情、一级行业成分、概念成分都走东财 push2。板块行情与一级行业成分会缓存（内存 30 分钟 + 磁盘 `data/cache/pick_*.json` 6 小时，点「刷新板块」强制重取），没缓存时展开一个行业约 0.3-2 秒。东财不可用时：行业行情自动回退成**成分股聚合**（涨跌幅中位数 / 主力净占比均值 / 成交额合计 / 涨跌家数），概念取不到就跳过，降级项逐条写在页面与产物里。
- **荐股没有财务数据**：本轮不抓 ROE / 分红 / 财报，只有行情与估值（PE / PB）。长线模块因此只用估值分位 / 市值 / 动量，模型被要求在「降级与不确定性」里写明这一点。
- **荐股不再包含指数**：「指数」这个板块类型已移除（指数只在「大盘快照」页展示）。历史产物里若还有指数列，页面仍能打开查看。
- **概念主题是本地关键词表**：16 个主题 + 「其他」（实测 504 个概念里落「其他」的只有 11 个）。未命中的概念照样能用搜索找到并勾选；勾选上限 120 个（每个概念 1 次请求）。
- **只抓选中的板块**：未选的一律不拉取；候选总数超过「候选上限」时按板块热度从高到低截断。
- **候选榜共 30 只、一票一模块**：四个模块各自打分后合并去重；每个模块先按自身排名保底 3 只（保证模型对每个模块都有可选标的），剩余名额按全局最高机械分补足到 30，并归到该股分数最高的那个模块。所以同一只股票只占一行、模块列只有一个模块标签（早期产物可能仍带多模块标签，页面照旧能打开）。
- **模块可多选**：一次可选 1-4 个模块，每个模块各自一套打分权重；产物里的 `参数.模块` 就是所选模块列表，总控台荐股榜也按它筛选。多选会让事实包变大，超过 40000 字符时按既有逻辑截断并写进「降级」。
- **全选会很大**：全选 31 个一级行业会连带全部二级细分（实测合计约 128 个细分板块），抓取更久、候选池更大；页面会先弹确认，建议同时把「候选上限」调小。
- **中途取消**：在抓板块 / 抓成分阶段取消会立刻停止且不落盘；如果已经进入模型调用，会在模型返回后丢弃、同样不落盘（页面状态显示「已中断」）。

| 现象 | 处理 |
|---|---|
| 端口被占用 | 启动信息里会给实际端口（8765 起自动顺延 20 个）；也可 `--port` 指定 |
| 页面提示「账户配置不存在」 | 先跑 `python aiplan.py init-account`，并填真实「总资金」 |
| 报告页空白 | 先跑一次 `python aiplan.py post --code 002463.SZ --no-fetch --dry-run`（零成本）确认事实包能生成 |
| 大盘快照无数据 | 先跑一次 `python pan.py post`，页面读的是 `data/pan/<日期>/latest_post.json` |
| 想还原误改的配置 | 同目录 `.bak` 即保存前的原文件，直接改名覆盖即可 |
| 想找回删掉的报告 | 「历史与复盘」页最下方的**回收站**里点「恢复」；或手动把 `data/ai/.trash/<日期>/` 里的文件搬回 `data/ai/<日期>/` |
| 批量研判中途想停 | 点「中断」：当前这只跑完就停，已完成的报告都会保留 |
| 荐股报「所选板块没有取到任何数据」 | 东财接口不可用（限流或断网）、或所选细分名已变：稍后重试；点「刷新板块」重建缓存 |
| 荐股筛选区一直显示「板块数据加载中…」 | 首次加载要拉 31 个一级行业 + 504 个概念行情（约 1-2 秒）；失败时右侧会给出错误原文 |
| 展开行业看不到细分 | 该行业的成分股取数失败：看提示行（细分加载失败：…），点「刷新板块」或稍后重试 |
| 点「全选本页」没反应/提示上限 | 概念页全选受 120 个上限约束：先用搜索缩小范围再全选；行业页超过 6 个会先弹确认 |
| 模块至少要留一个 | 取消最后一个会被拦下：先勾上新的，再取消旧的 |
| 切了 model 但研判还是老模型 | 「模型配置」页那个带「自检用」的下拉**只影响自检**；改默认要用上面的「默认 profile → 保存默认」，或直接点某张 profile 卡片上的「设为默认」（写回 `config/模型配置.json`，留 `.bak`，只动 `默认_profile` / `profiles_by_phase` 两个键）。运行页「高级选项 → profile」是单次临时覆盖 |

| 想一次研判多只 | 运行页「标的代码」支持多选：输入后回车 / 点「加入」，或点「多选」勾选（最多 30 只）。多只会走**顺序批量**（每只各出一份报告，单只失败不中断，可「中断」），确认框里可「跳过复核省一半」；「清空」或 chip 上的 × 可移除单只 |
| 运行页填过 API Key 后一直 401 | 「高级选项 → 覆盖模型与 Key」里的 `--api-key` / `--api-base` **优先级最高**，会把配置里的 Key 盖掉（页面会红字提示；填错就是 `401 invalid api key`）。清空那两个框（或 Ctrl+F5 刷新页面）即可；要看当前到底用哪把 key，去「模型配置」页看 provider 表的「Key / 来源」列 |
| 荐股只有板块、没有候选股 | 成分股取数失败或全被排除规则过滤：看页面「数据依赖与降级」逐条会写明；放宽排除规则或稍后重试 |

| 加标的时报「会超过流资金」 | 流内所有标的的分配资金之和不能超过流资金：先点「改流参数」调大流资金，或把别的标的的分配资金改小，也可以直接移除一只标的 |
| 加标的时报「该标的在交易流 F-… 里还没结束」 | 一只标的只属于一条流：去那条流里把它结束 / 移除，或换一只标的 |
| 明明填了 6 位代码却提示「请填 6 位证券代码」 | 已修（2026-09-15）：接口同时认中文键 `代码` 与英文键 `code`，页面表单发的是前者 |
| 卡片里不知道计划是哪个打法的 | 每只标的旁边有打法徽章（超短线 / 短线 / 波段），计划产物里也记了「打法」与「打法规格」；改打法点行内「改打法」后重算计划 |
| 生成时提示「还没录入上一份计划的执行情况」 | 那几只标的会被跳过（日志里 `[WARN]`）：在详情卡的执行录入表里逐条填好状态（可先「全部标为未执行」）再生成 |
| 跟踪详情显示「计划已过期」 | 最新产物超过 3 天没更新：建议按当前行情重新生成一份 |
| 跟踪产物想删掉 | 详情卡「历史计划」里每行有「删除」：JSON + MD + 执行记录一起移入回收站（`data/ai/.trash/`），超过 7 天才真删 |
| 跟踪生成很慢 | 每只标的一次模型调用 + 一次批量报价；事实包越大越慢，可在「高级选项」里调小字符上限（账户 / 上一份计划 / 执行记录不会裁） |
| 跟踪页现价显示「stock3d 缓存」 | 还没取实时价：点「刷新实盘价」，或进入页面时自动刷一次；取不到就按缓存价并明确标注来源 |
| 荐股榜的模块按钮显示「（无）」并置灰 | 那份产物没跑这个模块：在荐股页把这 4 个模块都勾上重跑 |
| 只有 30 只候选 | 有意如此：四个模块合并去重后共 30 只（每模块保底 3 只 + 全局最高机械分补足）；总控台榜单也是这 30 只按推荐度排序 |
| 各模块候选数不均（如短线 21 / 波段 3 / 中线 3 / 长线 3） | 正常：一票一模块，按该股机械分最高的模块归属；保底数由 `PICK_MODULE_MIN` 决定，想更平均就调大它 |
| 榜单行数比候选少 | 正常：同一只股票在多个模块上榜会合并成一行，模块列会列出它在哪几个模块入选 |
| 控制台日志出现 `ConnectionAbortedError` / `ConnectionResetError` / WinError 10053 | 浏览器刷新、切页或取消轮询时取消了还没读完的请求：服务端已按「客户端断连」处理，不回 500、不打 traceback、不写盘，后续请求照常（2026-09-14 起） |
| 刷新变慢或提示「连续失败 N 次，已退避」 | 行情接口被限流或断网：程序自动按 2 倍退避（最长 5 分钟），恢复后回到所选档位；也可手动点「刷新实盘价」重试 |
| 实盘复核显示「最近收盘价」「昨收」 | 非交易日或还没开盘：这是真实口径，不是 bug；盘中会变成实时价 |
| 实盘复核提示「已降级为 stock3d 缓存价 / 报告内现价」 | 东财实时行情取不到（限流或断网）：卡片会写明来源与时间，机械结论仍可用，点「刷新实盘价」重试 |
| 点「生成当前时段点评」后只有机械结论 | 模型调用失败：卡片会显示失败原因，产物仍落在 `data/ai/plancheck/`，不会掩饰成成功 |
| 回收站里的文件不见了 | 说明已超过 7 天被自动真删（回收站卡片会显示上次清理时间与删除数量），这类删除不可恢复 |
